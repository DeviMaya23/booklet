# Verse Management Specification

## Purpose

Defines the data model, CRUD endpoints, ownership rules, and recency tracking for verses — narrative groupings (universes, settings, canons) that a user can assign to characters.

---

## Requirements

### Requirement: Verse data model
The `verses` table SHALL use the following schema:
- `id` — `uuid` PK, generated by the application
- `user_id` — `uuid`, FK referencing `users(id)`, not null
- `name` — `text`, not null
- `last_used_at` — `timestamptz`, nullable
- `created_at`, `updated_at` — `timestamptz`, not null
A composite unique constraint `UNIQUE(user_id, name)` SHALL be enforced at the database level.

#### Scenario: Unique constraint per user
- **WHEN** a user creates a verse with a name they already have
- **THEN** the system SHALL return 409 Conflict

#### Scenario: Same name allowed for different users
- **WHEN** two different users each create a verse with the same name
- **THEN** both SHALL succeed

---

### Requirement: Create verse
An authenticated user SHALL be able to create a verse by providing a `name`. The system SHALL return 201 with the created verse on success.

#### Scenario: Successful create
- **WHEN** an authenticated user POSTs `{"name": "Solaris"}` to `POST /verses`
- **THEN** the system returns 201 with the verse object including `id`, `name`, `last_used_at`, `created_at`, `updated_at`

#### Scenario: Name is required
- **WHEN** the request body omits `name` or passes an empty string
- **THEN** the system returns 422 Unprocessable Entity

---

### Requirement: List verses
An authenticated user SHALL be able to list all verses they own, ordered by `last_used_at DESC NULLS LAST, name ASC`.

#### Scenario: Ordering by recency then name
- **WHEN** a user has verses with mixed `last_used_at` values, including nulls
- **THEN** the list returns them in `last_used_at DESC NULLS LAST, name ASC` order

#### Scenario: Empty list
- **WHEN** a user has no verses
- **THEN** `GET /verses` returns 200 with an empty array

---

### Requirement: Get verse by ID
An authenticated user SHALL be able to retrieve a single verse by ID, provided they own it. A verse belonging to another user SHALL return 404.

#### Scenario: Own verse found
- **WHEN** an authenticated user GETs `/verses/:id` for a verse they own
- **THEN** the system returns 200 with the verse object

#### Scenario: Another user's verse
- **WHEN** an authenticated user GETs `/verses/:id` for a verse they do not own
- **THEN** the system returns 404

---

### Requirement: Update verse name
An authenticated user SHALL be able to update the `name` of a verse they own via `PATCH /verses/:id`. Only `name` is updatable. The unique constraint still applies after update.

#### Scenario: Successful name update
- **WHEN** an authenticated user PATCHes `/verses/:id` with `{"name": "New Name"}`
- **THEN** the system returns 200 with the updated verse

#### Scenario: Rename to existing name conflicts
- **WHEN** the new name matches another verse the user already owns
- **THEN** the system returns 409 Conflict

#### Scenario: Empty name rejected
- **WHEN** the PATCH body contains an empty string for `name`
- **THEN** the system returns 422 Unprocessable Entity

---

### Requirement: Delete verse
An authenticated user SHALL be able to delete a verse they own. Deleting a verse SHALL set `verse_id` to null on all characters that referenced it (`ON DELETE SET NULL` via the FK definition). The delete SHALL return 204 No Content.

#### Scenario: Delete clears character references
- **WHEN** a verse that is assigned to one or more characters is deleted
- **THEN** those characters SHALL have their `verse_id` set to null
- **AND** the characters themselves are not deleted

#### Scenario: Delete own verse returns 204
- **WHEN** an authenticated user DELETEs `/verses/:id` for a verse they own
- **THEN** the system returns 204

#### Scenario: Delete another user's verse
- **WHEN** an authenticated user DELETEs `/verses/:id` for a verse they do not own
- **THEN** the system returns 404

---

### Requirement: Verse last_used_at tracking
`verses.last_used_at` SHALL be set to the current timestamp whenever a character's `verse_id` is set to that verse (on character create or update). It SHALL NOT be updated when the verse's own `name` field is edited.

#### Scenario: Create character with verse bumps last_used_at
- **WHEN** a character is created with a non-null `verse_id`
- **THEN** `verses.last_used_at` for that verse is set to approximately now

#### Scenario: Update character with new verse bumps last_used_at
- **WHEN** a character is updated and `verse_id` changes to a non-null value
- **THEN** `verses.last_used_at` for the newly assigned verse is set to approximately now

#### Scenario: Editing verse name does not bump last_used_at
- **WHEN** a PATCH updates the verse's `name` without any character assignment
- **THEN** `verses.last_used_at` remains unchanged

---

### Requirement: Verse ownership isolation
The system SHALL ensure a user cannot read or modify verses belonging to another user. All queries SHALL be scoped to the authenticated user's ID.

#### Scenario: Cross-user isolation on list
- **WHEN** user A lists verses
- **THEN** only user A's verses are returned, never user B's

---

### Requirement: Verse response shape
Every verse response SHALL include:
- `id` (string, UUID)
- `name` (string)
- `last_used_at` (string, RFC3339, or null)
- `created_at` (string, RFC3339)
- `updated_at` (string, RFC3339)

#### Scenario: Verse response fields present
- **WHEN** any verse endpoint returns a verse object
- **THEN** all five fields are present with the correct types
