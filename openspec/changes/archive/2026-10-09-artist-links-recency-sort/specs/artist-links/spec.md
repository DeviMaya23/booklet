## ADDED Requirements

### Requirement: Artist links data model
The `artist_links` table SHALL use the following schema:
- `id` — PostgreSQL `uuid` type, primary key, generated by the application
- `artist_id` — `uuid`, foreign key referencing `artists(id)` with `ON DELETE CASCADE`, not null
- `url` — `text`, not null
- `is_primary` — `boolean`, not null, default `false`
- `created_at` — `timestamptz`, not null
- `updated_at` — `timestamptz`, not null

An artist MAY have zero, one, or many links. At most one link per artist SHALL have `is_primary = true`; this is enforced at the application layer.

#### Scenario: Links deleted when artist is deleted
- **WHEN** an artist is deleted
- **THEN** all rows in `artist_links` referencing that artist SHALL be deleted automatically via CASCADE

#### Scenario: Zero links is valid
- **WHEN** an artist has no rows in `artist_links`
- **THEN** the artist is still valid and fully functional

#### Scenario: At most one primary per artist
- **WHEN** an artist's links are saved with more than one entry marked `is_primary: true`
- **THEN** the application SHALL coerce all but the first to `is_primary: false` before persisting

---

### Requirement: Links managed inline on artist create and update
Artist links SHALL be accepted as a `links` array in the artist create (`POST /artists`) and update (`PUT /artists/:id`) request bodies. Each element SHALL have:
- `url` — required, must be a valid URL (scheme required)
- `is_primary` — required boolean

On update, the system SHALL replace all existing links for the artist with the submitted set (delete-then-insert). Empty or absent `links` array results in the artist having no links.

Each `url` SHALL be validated as a syntactically valid URL; an invalid URL in any element SHALL cause the entire request to return 422.

#### Scenario: Create artist with links
- **WHEN** an authenticated user sends `POST /artists` with a valid `links` array
- **THEN** the system returns 201 and the artist response includes the submitted links

#### Scenario: Update artist replaces all links
- **WHEN** an authenticated user sends `PUT /artists/:id` with a new `links` array
- **THEN** all previous links for that artist are deleted and replaced with the submitted set

#### Scenario: Update artist with empty links clears all links
- **WHEN** an authenticated user sends `PUT /artists/:id` with `"links": []`
- **THEN** all existing links for that artist are deleted and the response contains an empty `links` array

#### Scenario: Invalid URL in links array
- **WHEN** an authenticated user sends `POST /artists` or `PUT /artists/:id` with a `links` element whose `url` is not a valid URL
- **THEN** the system returns 422

---

### Requirement: Primary link resolution
Wherever a single artist link is surfaced in an API response, the system SHALL use the primary link — the link with `is_primary = true` for that artist. If no primary link exists, the field SHALL be `null`.

This applies to:
- Commission responses (`artist_link` field): resolved to the primary URL of the assigned artist
- Artpiece responses: resolved to the primary URL of the assigned artist (where applicable)

#### Scenario: Commission response includes primary link
- **WHEN** a commission has an assigned artist with a primary link
- **THEN** the commission response's `artist_link` field SHALL contain that link's URL

#### Scenario: No primary link yields null
- **WHEN** an artist has no link with `is_primary = true`
- **THEN** any response field resolving to that artist's primary link SHALL be `null`
